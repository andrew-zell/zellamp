# Zellamp: development

Zellamp is an Electron app. The main process talks to the music player (AppleScript on macOS, the system media session on Windows) and owns the windows. The renderer runs [Webamp](https://github.com/captbaritone/webamp) for classic skins and its own SVG player for freeform skins. User-facing docs are in [README.md](README.md).

## Layout

```
src/
  main/                 main process
    index.ts            windows, menus, tray, IPC, setup actions, About
    stateBridge.ts      the authoritative player state (see Notes › State)
    sources/            where "what's playing" comes from (MediaSource)
      macSpotify.ts     macOS: Spotify via osascript
      windowsMedia.ts   Windows: system media session via a PowerShell helper
    player.ts           the player-sized window: layout, drag, snap
    hitTest.ts          click-through decisions (cursor polling)
    themes.ts           skin library: bundled + installed, validation
    config.ts           config.json load/save/migrate
    trayIcon.ts         GENERATED by npm run icon
  preload/index.ts      the only bridge to the renderer (contextBridge)
  renderer/             one Vite app, four pages
    index.html, main.ts the player: Webamp, SkinSwitcher, menus, sync
    freeform.ts         freeform SVG player (+ freeform.css)
    playerMenu.ts       the right-click menu (+ playerMenu.css)
    artPanel.ts         album art docked to the classic player
    spotifyMedia.ts     Webamp's __customMediaClass, forwarding to main
    visSource.ts        system-audio capture → AnalyserNode for the visualizer
    skinKit.ts, waui.ts Winamp-style UI kit built from the active skin
    gallery.*, setup.*, about.*   Skin Browser, Setup Assistant, About
  shared/types.ts       types and IPC channel names shared by all three
resources/
  themes/               bundled skins (GENERATED: npm run themes / skins)
  windows/media-helper.ps1   the Windows media helper (shipped as-is)
  icon.png/.icns/.ico   GENERATED by npm run icon
  entitlements.mac.plist
scripts/
  dev.sh                run the dev build with debug hooks
  make-release.sh       gated release build (both platforms)
  debug/cdp.mjs         drive a running dev build (eval, screenshots, clicks)
  themes/               generator for the classic skins
  freeform/             freeform skin sources (*.svg) + sync into resources
  icon/build-icon.mjs   pixel-art icon → every icon file
  dmg/                  DMG background
  extract-base-skin.mjs Winamp base skin sprites from Webamp's bundle
  sign.cjs              electron-builder afterSign: local certificate re-sign
tests/                  vitest unit tests
docs/                   screenshots, freeform skin guide
```

## Prerequisites

- Node 22+ and npm.
- macOS to build the Mac app. The Windows installer also builds on macOS (electron-builder's NSIS needs no Wine for this config).
- If `npm run dev` says "Electron uninstall", the Electron binary didn't download during install: `node node_modules/electron/install.js`.

## Run

```sh
npm install
npm run dev                 # electron-vite with watch: main/preload changes restart the app
./scripts/dev.sh            # same, plus the CDP debug port (9333)
./scripts/dev.sh --fresh    # throwaway profile: first-run state, and runs beside an installed Zellamp
./scripts/dev.sh --about    # also --gallery, --setup: open that window at launch
```

Renderer changes hot-reload, but the player page doesn't always pick up a change to `main.ts`; `node scripts/debug/cdp.mjs reload` forces it.

**Permissions in dev** attach to `Electron.app`, not Zellamp, so macOS asks again for the dev build.

## Tests

```sh
npm test          # vitest
npm run check     # typecheck + tests (the release gate)
```

What's covered, and why:

- `tests/stateBridge.test.ts`: the state rules that keep the UI from flickering: optimistic play/pause freezes the position at the press; a read that started before a command is discarded and redone (it would undo the command); one failed read is ignored, three report an error; the track clears when the player goes away; an event repeating the current track keeps its artwork.
- `tests/pixelScale.test.ts`: panels land on whole device pixels at every display density. Fractional scales smeared the bitmap fonts on a 1x 1440p display.

UI behavior is verified against a running dev build with `scripts/debug/cdp.mjs` (see Debug tooling).

## Bundled skins

- **Classic:** `npm run themes` regenerates `resources/themes/*.wsz` and `themes.json`. Add a recipe to `scripts/themes/themes.cjs`; no code change needed. The pipeline: `extract-base-skin.mjs` pulls the base skin's sprites from Webamp's bundle → `themes/sheets.js` rebuilds real Winamp sprite sheets → `themes/engine.js` classifies every pixel (chrome, LCD, gold, red) and maps each class through the recipe's color ramps, adds a texture, re-letters the title bars → real `.wsz` files that work in any Winamp-compatible player.
- **Freeform:** drop an SVG in `scripts/freeform/` and run `npm run skins` (copies them in and updates the manifest). Format: [docs/freeform-skins.md](docs/freeform-skins.md).

## Icons

`npm run icon` draws every icon from the pixel art in `scripts/icon/build-icon.mjs`: `resources/icon.png` (1024), `icon.icns` (macOS, via `iconutil`), `icon.ico` (Windows) and `src/main/trayIcon.ts` (menu bar template + Windows tray).

- Two drawings: the 64×64 app icon (body 52×52 cells = Apple's 832/1024 grid) and a 16×16 small icon for 16–48 px. Every size is a whole-number scale of one of them, so nothing is resampled. A smoothly shrunk 1024 turned to mush below 64 px.
- The menu bar icon is a template (black + alpha): macOS recolors it for light and dark menu bars.

## Dev hooks (env vars)

All are ignored in packaged builds.

- `WR_DEBUG_PORT=<port>`: open the Chrome DevTools Protocol port (`scripts/dev.sh` sets 9333). Attach DevTools at `chrome://inspect`, or use `scripts/debug/cdp.mjs`.
- `WR_USER_DATA=<dir>`: use this profile directory instead of the real one (`--fresh`). The single-instance lock is per profile, so this is also how a dev build runs next to the installed app.
- `WR_OPEN_GALLERY=1` / `WR_OPEN_SETUP=1` / `WR_OPEN_ABOUT=1`: open that window at launch.

The `WR_` prefix is from the project's first name, "winamp-remote".

**Page globals (dev builds):** in the player page, `window.__webamp` (the Webamp instance; `__webamp.store` is its Redux store), `window.__skins` (SkinSwitcher: `hitRegion()`, `setZoom()`), `window.__vis` (VisSource). In the Skin Browser, `window.__kit` (the active SkinKit). Every page has the preload APIs: `window.spotify`, `window.widget`, `window.themes`, `window.setup`, `window.about`.

## Debug tooling

`scripts/debug/cdp.mjs` drives a dev build started with a debug port:

```sh
node scripts/debug/cdp.mjs pages
node scripts/debug/cdp.mjs eval '__webamp.store.getState().windows.genWindows'
node scripts/debug/cdp.mjs eval "window.themes.apply('orb')"
node scripts/debug/cdp.mjs shot out.png --clear        # transparent background
node scripts/debug/cdp.mjs --page gallery.html shot browser.png
node scripts/debug/cdp.mjs rclick 120 60               # opens the right-click menu
```

Lessons:

- **Use real input events.** `cdp.mjs click/rclick/hover` sends trusted mouse events through Chromium, so capture-phase listeners, `:hover` and Webamp's own handlers all see them. Calling `element.click()` from `eval` skips `pointerdown` and can pass where a real click fails.
- **The window resizes around what's open.** The player window is sized to the player, so a screenshot's size tells you what's showing (e.g. 295×252 means the playlist is open), and an opening menu should grow it.
- **Screenshots of the player page** are the window's own pixels: they don't show the desktop behind, and window-server behavior (Mission Control outline, focus, click-through) has to be checked by eye.
- **Windows** can't be tested from here. The helper logs to `%APPDATA%\Zellamp\media-helper.log`.

## Releasing

```sh
./scripts/make-release.sh 0.2.0
```

Bumps the version, runs the gate (typecheck + tests), builds the DMG and the Windows installer, writes `dist/SHA256SUMS.txt`, and prints the commands to tag and publish with `gh release create`.

**Mac signing today:** `scripts/sign.cjs` re-signs with a self-signed certificate named `Zellamp Local Signing` when one exists. That gives the app a stable identity on *your* Mac, so privacy permissions survive rebuilds (an ad-hoc signature is a hash of the build, so each rebuild looked like a new app and System Settings kept stale entries). Create it once: Keychain Access › Certificate Assistant › Create a Certificate…, name `Zellamp Local Signing`, Self-Signed Root, Code Signing. It does nothing for other people's Macs.

**For a public release (not set up yet):**

1. Apple Developer Program membership ($99/yr) → a **Developer ID Application** certificate (developer.apple.com › Certificates; create the CSR with Keychain Access › Certificate Assistant › Request a Certificate From a Certificate Authority).
2. Notarization credentials for electron-builder: set `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` (appleid.apple.com › Sign-In and Security) and `APPLE_TEAM_ID`, then add `"notarize": true` under `build.mac` and set `build.mac.identity` to the Developer ID. `sign.cjs` currently re-signs whenever the local certificate exists, which would replace the Developer ID signature: make it skip in that case.
3. Optional: a universal (`--universal`) build for Intel Macs, and Authenticode signing for Windows (Azure Trusted Signing is the cheapest) to clear SmartScreen.

## Config and data

- macOS: `~/Library/Application Support/Zellamp/`. Windows: `%APPDATA%\Zellamp\`.
- `config.json`: always on top, Dock visibility, zoom, album art, active skin, player position per skin, Webamp window layout. Old keys are migrated in `config.ts` (`doubled` → `zoom: 2`; full-screen-era `layout` dropped).
- `themes/`: installed skins. `media-helper.log` (Windows).

## Notes

How each part works, and why it's built that way. Newest decisions are dated.

### Media sources

`sources/types.ts` defines `MediaSource`: `read()`, `run(command)`, `watch(onEvent)` and an `idleText`. `createSource()` in `index.ts` picks one per platform. The player UI never knows which.

**macOS (`macSpotify.ts`).** Two static AppleScripts run through `osascript`; arguments only ever go through argv, never string-built scripts. A read is one Apple Event for all player-level properties (`properties` of the application), plus the track ID; full metadata (and the artwork URL) is only fetched when the ID changes, so a steady-state read is ~120 ms. Spotify returns `missing value` mid-transition for position and volume; those are guarded. Changes arrive instantly through Spotify's distributed notification `com.spotify.client.PlaybackStateChanged`, whose payload is applied before the confirming read.

**Windows (`windowsMedia.ts` + `resources/windows/media-helper.ps1`).** A long-running Windows PowerShell 5.1 helper uses the WinRT `GlobalSystemMediaTransportControlsSessionManager` (the API behind the volume flyout's media panel), prefers Spotify's session and otherwise follows the current one, so browser players work for free. It speaks JSON lines over stdio: `state` messages when anything changes, `ack`s for commands. Volume is per-app through Core Audio (a small C# shim compiled by `Add-Type`). Hard-won details (2026-10):

- **`-MTA`.** In PowerShell's default STA the WinRT session objects never update after the first read: track changes from the browser didn't show until a command was sent.
- **Raw stdio streams.** `[Console]::ReadLine` blocking on another thread also blocks `[Console]::Out` writes in PowerShell 5.1, so state updates stalled until a command arrived. The helper reads stdin in a background runspace into a queue and writes through its own `StreamWriter` on `OpenStandardOutput()`. `Console.In.ReadLineAsync` blocks too; don't use it.
- **Play/pause land late.** Right after a command the session still reports the old state for a few hundred ms, so pressing pause twice could invert what the UI showed. `run()` holds the expected state for up to 1.5 s (freezing or resuming the position from the moment of the press), and the helper polls fast (120 ms) for 1.5 s after any command.
- **Position** is `Position − StartTime` sampled at `LastUpdatedTime`; the renderer extrapolates from there. Spotify updates it often; browsers mostly only on play, pause or seek, so a browser track can drift until its next update. Not fixable from this API: a browser extension would be the real fix.
- The installer ships the `.ps1`; the app runs it with `-ExecutionPolicy Bypass` from its resources folder.

### State

`stateBridge.ts` keeps one `SpotifyState` in main and pushes every change to the renderer. Events from the source are applied at once, then confirmed by a read; polling resyncs every 5 s, or every 500 ms if events seem to be missing (a change a read finds without an event, twice). Commands apply optimistically. A read issued before the latest command is thrown away and redone, since its result may predate the command. One failed read is ignored; only a streak of three reports an error. Pinned by `tests/stateBridge.test.ts`.

### The player window

- **Sized to the player, not the screen** (2026-10). It started as a transparent overlay over the whole display, which made Mission Control draw a display-sized outline and kept the player on one display. Now the renderer reports the rect it draws (`playerLayout`), main sizes the window to it and returns the offset, and the page shifts Webamp's windows to match so nothing moves on screen.
- **Dragging is done by main** (`player.ts`): on mousedown the page calls `dragStart`; main follows the cursor at 8 ms and snaps within 12 px of a display's work-area edge. A page can't move its own window smoothly across displays.
- **In-page drags** (undocking the playlist from the main window) need room: `expand()` grows the window to the display's work area for the drag, then `layout()` shrinks it back.
- **Click-through** (`hitTest.ts`): main polls the cursor at ~30 Hz against regions the page reports (window rects, menus, and an alpha mask for freeform skins) and toggles `setIgnoreMouseEvents` before a click lands. Forwarded mousemove events from the page were racy: a click could fall through to the app underneath and bring it in front.
- **Menus grow the window** to the right and down while open (`playerGrow`), and it shrinks back on close.

### Webamp integration

- **One placeholder track.** Webamp's playlist holds a single track whose tags are rewritten with whatever's playing; its URL is never fetched. `spotifyMedia.ts` is Webamp's `__customMediaClass`: Webamp drives it like an audio element and it forwards to main, reporting the interpolated position back.
- **`guardMiddleware`** (`main.ts`): drops playlist edits and the next/prev Webamp resolves against its one-track playlist (the real buttons are routed in `interceptTransportClicks`), forwards shuffle/repeat, and swallows the reposition Webamp dispatches right after `BROWSER_WINDOW_SIZE_CHANGED` (its "keep windows on screen" pass fights the player-sized window).
- **EQ hidden, playlist closed by default** (2026-10). Zellamp can't shape another app's audio, so the EQ did nothing: it's closed at launch (closing the gap if the playlist was docked under it) and toggling it is blocked. The playlist only ever shows the current track, so a first run (or Reset Window Positions) shows just the main window; it's still in the right-click menu.
- **Double size** is off; Zellamp's Zoom replaces it.

### The right-click menu (2026-10)

The menus used to differ by skin: Webamp's own menu on classic skins, a native popup on freeform ones. Now there's one, built in main (`playerMenuItems()` in `index.ts`, so it shares the skins list, zoom and options with the native menus) and drawn in the page in Webamp's menu style (`playerMenu.ts`). Main serializes the template (`serializeMenu`), keeps the click handlers, and the page sends back an index. `slot` items are filled in by the page (the Playlist Editor toggle, classic skins only). Webamp's own menus are intercepted in the capture phase: right-click anywhere, the title bar's menu button, and the clutter bar's "O". Submenus open with inline styles rather than `:hover`, so the layout and hit-region watchers see them.

### Pixel scaling

- **Zoom** (100/150/200/300%): CSS zoom on `#webamp`. When zoom × devicePixelRatio is whole, nearest-neighbor is exact. 150% on a 1x display isn't: the player renders at 2× with hard pixels and is scaled down smoothly ("sharp bilinear"), which spreads the softening evenly instead of making uneven pixel columns.
- **Panels** (Skin Browser, Setup, About) are 500×348 skin pixels at `panelScale(dpr)`: 2 device pixels per skin pixel on 1x displays, 3 on dense ones. They use CSS zoom, not `webContents.setZoomFactor`: Chromium shares zoom across same-origin windows, which also scaled the player.
- **Panel title text** is drawn with a fixed pixel font, not each skin's: per-skin anti-aliasing fixes changed with every skin.

### Skin kit (`skinKit.ts`, `waui.ts`)

Zellamp's own windows are built from the active classic skin: chrome and title font from `gen.bmp`, lettering from `text.bmp`, list colors from `pledit.txt`, bevels sampled from the chrome. A freeform skin names a classic skin to dress the panels (`data-za-panel`).

### Visualizer

`visSource.ts` captures system audio (`getDisplayMedia` loopback; main's display-media handler drops the video) into an `AnalyserNode` that Webamp's own visualizer and freeform skins read. Captured audio is auto-gained against the player's volume, and the AudioContext suspends when nothing plays or the player is hidden. Without audio access a synthetic animation runs while playing. macOS needs Screen & System Audio Recording for this (granted once per signing identity; see Releasing); Windows needs nothing.

### Permissions (macOS)

Privacy permissions (Automation › Spotify, Screen & System Audio Recording) are tied to the app's signature. Stale entries from older builds look switched on but deny access; the Setup Assistant detects this and says to remove the entry with **−** and grant again. macOS doesn't tell apps when a privacy switch flips, so the Setup window polls every 1.5 s while open.

## Ideas

- A browser extension source: exact position and control for browser players on both platforms.
- Spotify-only audio: a Core Audio process tap on macOS 14.2+ (also removes the screen-recording permission), per-process loopback on Windows.
- Notarized, universal Mac build; signed Windows installer.
